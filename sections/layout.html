layout

Compose & wireframe a screen

Structure without a single hand-set pixel. The .page shell is a ten-slot application grid; the layout primitives are zero-specificity composition helpers whose gap derives from line-height; the overlays are native <dialog> / popover with the engine's paint. All spacing is em/lh, so it tracks type. Together they are the wireframing kit — rough a whole screen out of them before you style a thing.

The recommended path

calcified

Five moves, outside-in. Follow them and a screen composes itself — no spacing scale, no media-query bookkeeping, no z-index.

1
Pick the frame.A whole app → .page + the pg-* slots you need. A sub-view that owns its scroll → .hero (top / left / main / right / bottom). Leave a slot out and its track collapses.
2
Fill each region by composing primitives.Reach for .column and .row first; .grid for cards, .split for two panes, .spread/.lcr for bars, .flank for icon·text. Nest them freely — they gap at 0.25lh, so rhythm is automatic. Never hand-set padding.
3
Rough content in as bare boxes.A .card with a --bg step is a placeholder; a bare element at a --type is a label. You're wireframing in the real engine, so the greybox already has the right rhythm and color — it just gets replaced, never re-laid-out.
4
Adapt with the gate classes, not new CSS.Show a sidebar only on .desktop, a bottom bar only on .mobile, a fatter target only on .coarse; let a component react to its own box with .small/.medium/.large. They compose and cost nothing — see below.
5
Name what will move.If a region animates between states, give it .vt style="--vt:name" now — the wireframe becomes the transition storyboard for free. See View transitions.

  <header class="pg-header spread"> brand · actions </header>
  <nav class="pg-navigation desktop column"> …links… </nav>   <!-- ≥1024 only -->
  <main class="pg-main">
    <div class="grid" style="--grid-min:16rem">               <!-- card wall -->

</div>

The .page shell

Responsive & pointer

Show or hide by breakpoint or input device via display: revert-layer in the last layer. Because everything is layered, these just win — no specificity fights, and the hidden copy leaves the tab order + a11y tree entirely. Resize the window to watch the viewport tags swap.

.mobile · .tablet · .desktop Viewport width — <768 · 768–1024 · ≥1024. One shows at a time:
mobiletabletdesktop← your viewport
.fine · .coarse Pointer type — mouse vs touch:
fine (mouse)coarse (touch)

.small · .medium · .large do the same against a container (with a container-type ancestor), so a component adapts to the space it's in, not the viewport. Because we can depend on the layer order, it just works.

<aside class="desktop">Sidebar</aside>   <!-- ≥1024px only -->
<button class="coarse">Tap</button>      <!-- touch pointers only -->
<div class="large">Wide layout</div>     <!-- container ≥560px -->

Overlays

Native top-layer surfaces — no z-index, no JS positioning. A <dialog> gives focus-trap, Esc-close and an inert background for free; a popover light-dismisses and anchors to its trigger. They paint from the engine, so they theme automatically.
