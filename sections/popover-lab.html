Popover composition lab

A regression harness for one rule: a closed .menu[popover] must collapse to display:none no matter which composition classes it carries — otherwise the invisible panel stays laid out and eats the click that should open it.

The guard

classAPI.media

The browser already collapses closed popovers via the UA sheet — but author display (from .menu itself, or a stacked .column/.row/.grid…) outranks it. One central guard in the last layer re-asserts the collapse, so it wins over the layout layer for every popover — no per-class guards, no bare-wrapper rule.

@layer classAPI.media {
  :where(.menu[popover]):not(:popover-open) { display: none }
}

Stress test

on load, every closed popover reads none ✓

Each trigger opens a .menu[popover] carrying a different — and increasingly absurd — stack of composition classes. On load every popover is at rest and closed, and its badge reads its closed computed display: all say none ✓ — the guard collapses each one whatever layout classes it stacks. Open any to watch it lay out; the trigger stays clickable and it closes cleanly. (The badge only reads on load: display here rides an allow-discrete fade, and live-re-reading it mid-transition holds the transition open — the measurement is what sticks, not the popover. The at-rest load check is the real regression test; functionally the fix is that the closed panel no longer blocks its trigger.)
