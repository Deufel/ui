system.css

One stylesheet. Bare HTML is already the component. Colour and space are computed from a few signed numbers, not chosen from a palette. This is the whole API.

The model

Every element resolves its colour from three inherited numbers. You set position; the engine solves the pixels — for the live theme, hue, and whatever surface the element lands on.

VarAxisRangeMeans
--bgsurface depth−1 … 0 … +10 = base. Negative recedes (quieter). Positive advances toward the chromatic peak (louder).
--fgink−1 … 0 … +1Negative → neutral contrast pole (max legibility). Positive → chromatic pole (coloured ink). Contrast is auto-solved against the host surface.
--huehue0 … 360One number rotates the whole system.
--hue-shiftsubtree hue±degAdds into the live hue — rotates every non-locked descendant at once, so a whole panel re-hues with one declaration.
--hue-lockpin—Pins an element's hue against a shift; the four semantic helpers set it so meaning never rotates.
 
<div class="card" style="--bg:-0.3">recessed panel</div>
<span style="--fg:0.8">chromatic text</span>
--border and --focus are derived from the surface automatically — never set them; components opt in.

Surfaces & separation

Paint a surface with .bg, or use a named container. Nest by lifting, not by hand-picking darker values — a lifted child steps off whatever hosts it, so it stays correct on any surface.

ClassSeparation
.bgPaints its --bg; publishes lightness for child ink.
.card / .CardBordered panel — quiet line / vibrant line.
.surface / .SurfaceA --lift step, no line — for grouping inside a card.
--lift: nSit n above the host surface (relative). What every control uses so it reads on any background.

Type is the spacing system

One signed step, --type, sets size — and from it the engine derives leading, tracking, and weight together. Spacing is a fraction of the line (lh), so rhythm scales with type. No pixel grid, no spacing scale.

StepRole
5 … 1h1 … h5
0body · UI · controls
−1small
−2micro (tags, captions)
 
<h2 style="--type:4">Heading</h2>
<div class="row">…</div>   <!-- gap = calc(0.25 * 1lh), scales with type -->

--scale zooms a whole region (inherits); --type sizes one element (does not).

Meaning & state

Four semantic helpers lock a hue and commit ink to it — layer-independently, so a tag, an alert, and a button all speak the same meaning. State rides ARIA.

Don't hand-set padding

Spacing is the system's job. Compose with .row / .column / .grid and their lh-based gap, and let each component carry its own em-based padding. Padding added by hand fights the type-driven rhythm and breaks alignment the moment --type or data-ui-size changes. If something needs air, reach for a layout primitive, not a pixel.

Viewport & pointer gates

Six classes show or hide an element by context — nothing else. Each defaults to display:none; the matching query then flips it to display: revert-layer, which reverts the display to the previous cascade layer — restoring the element's natural display. This works only because these rules live in classAPI.media, the last layer: the gate out-ranks every component's display, and reverting lands exactly on the component's own value. Layer order is the mechanism. (Inline display still wins — don't set it on a gated element.)

ClassesGateBreakpoints
.mobile .tablet .desktopviewport width<768 · 768–1024 · ≥1024px
.small .medium .largecontainer width (needs a container-type ancestor)<320 · 320–560 · ≥560px
.fine .coarsepointermouse · touch
 
<aside class="desktop">Sidebar</aside>   <!-- ≥1024px only -->
<button class="coarse">Tap</button>      <!-- touch pointers only -->
<div class="large">Wide layout</div>     <!-- container ≥560px -->
None is the default. A plain element shows everywhere — no gate class is ever “on” by default. The moment you add one (say .mobile) it shows only in that range and is hidden in the other two. Gates compose: class="mobile desktop" shows on phone + desktop and hides on tablet.

App shell — .page slots

A .page is a ten-slot grid. Add a pg-* child and its slot appears; omit it and the track collapses. Only nav, main, and aside scroll — the shell itself never does.

Overlays — native top layer, no z-index

Every overlay is a native element, so the browser gives focus-trap, Esc, an inert background, and stacking for free.

.drawer .left/.right/.top/.bottom<dialog>showModal(); edge-anchored panel that slides in.
.menu<menu popover>popovertarget; anchors to its trigger, flips to stay on-screen, light-dismisses. Rows are flat full-width <button>/<a>.

View transitions

Motion helpers layered on the native View Transitions API. Inert until you opt in: wrap a DOM change in document.startViewTransition(update) and the browser snapshots before/after and animates between them. Set data-vt on <html> before starting to pick the direction.

data-vtMotion
fade (default)Crossfade.
slide-left · slide-rightNew content enters from the right / left.
scaleSubtle zoom crossfade.
zoomPronounced zoom crossfade.
 
document.documentElement.dataset.vt = "slide-left";
document.startViewTransition(() => render(next));

Duration rides --cfg-motion, so data-ui-motion (off/on/debug) and prefers-reduced-motion already govern it — at motion 0 the swap is instant. Give a shared element a unique view-transition-name to morph it (position/size tween) across the change. Cross-document transitions (same-origin page loads, zero JS) are one line: @view-transition { navigation: auto; } — left off by default. Unsupported browsers just run the callback with no animation, so it's safe to ship.

The laws

  1. Bare HTML is the component; add a class only to vary it.
  2. Never name a colour — declare a position (--bg/--fg) and let the engine solve it.
  3. Shape follows content; height is shared; spacing is a fraction of the line.
  4. State rides ARIA. Meaning rides the four semantic helpers.
  5. Everything you author wins — the system ships at specificity 0.
